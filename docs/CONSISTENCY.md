# 一致性、并发与持久化边界

本文档说明服务承诺什么、如何实现，以及不承诺什么。

## 1. 文档同步

每个文档有一个单调版本号与一个不可变快照 `DocumentSnapshot(uri, version,
text, lineIndex)`。所有变更在“每文档锁”内串行完成，且只在整次变更提交后
整体替换快照。

- **顺序编辑** `baseVersion == current`：应用，产生 `request.version`。
- **重复**：版本号、baseVersion、编辑集合（或全文）完全相同的已提交通知，
  返回 `DUPLICATE`，幂等，内容不变。同版本号但内容不同视为版本回退，返回
  `REJECTED_STALE`，绝不静默接受。
- **陈旧** `baseVersion < current`：
  - 默认 `REJECT`：返回 `REJECTED_STALE`，内容不变；
  - 可选 `REBASE`：把陈旧编辑的绝对偏移，按每个中间提交记录的绝对 span
    逐跳平移后应用（`REBASED`）；编辑若落在被后续提交删除的文本内、或中间
    存在全文同步，则无法平移，仍然拒绝。全文同步永远不能被陈旧 rebase。
- **乱序（未来）** `baseVersion > current`：
  - 默认 `BUFFER`：缓存该通知；缺口补齐后按版本号连续提交，状态为
    `APPLIED`（同一通知的 `appliedVersions` 给出本次连锁提交的版本）；
  - `REJECT`：立即拒绝；
  - 缓存有界（`max-buffered-changes`），超出返回 `REJECTED_FUTURE_LIMIT`。
- **重叠/重复**：同一通知内的多个编辑必须互不重叠（边界相触允许），按文档
  逆序原子应用；重叠则整次失败，不会部分应用。

编辑器真实状态不会因乱序、重叠、重复、回退或跳号而偏离：偏离编辑器真相的
通知都会被识别为 `DUPLICATE`/`REJECTED_*`/`BUFFERED`，而不是静默改写内容。

## 2. 增量分析

- **词法层**：只对编辑点周围被“加宽”的窗口重新分词。窗口边界向两侧移动到
  新旧两份文本中都处于 `CODE` 词法状态（绝不在标识符/字符串/注释内部切
  分），且保证没有 token 跨越边界；窗口外的 token 直接复用，编辑后的部分
  整体平移。
- **语法层**：只对包含编辑的最小作用域区域，用同一套语法在拼接后的 token
  上重新解析；祖先作用域只复制自身声明，并复用不与编辑相交的兄弟子树
  （编辑之前结束的偏移不变，其后的平移）。当区域的花括号平衡发生变化时，
  向外扩大重解析区域，最大到整份文档。
- **结果必须与从头重建一致**：每个增量结果都会与同文本的全量模型做结构化
  比较（`ModelsEquivalent`：作用域区间、类别、符号、偏移、token 流逐项相同）。
  一旦发现差异，立即丢弃增量结果并使用全量结果——外部结果因此始终等同于
  全量重建，而只有受影响区域在快路径上被重算。
- `SyntaxModel.incremental()` 标识模型是否实际由快路径产出（测试中验证
  窗口外 token 偏移保持不变）。

## 3. 并发

- **编辑 vs 查询**：编辑在每文档短临界区内提交，从不在查询线程池中排队；
  查询运行在独立的有界线程池，慢查询不会阻塞编辑（测试
  `CancellationTimeoutTest#slowQueryDoesNotBlockEdits`）。
- **快照隔离**：查询开始时固定一个不可变 `DocumentSnapshot` 与对应的不可变
  `SyntaxModel`；派生状态（模型、recent）在编辑后整体替换引用。任一查询
  只能读到某个**已提交的完整版本**，不可能读到半解析状态，也不可能出现
  跨版本的字段级混合；若查询期间文档已变更且模型版本不再匹配，则不写入
  缓存并返回与该快照一致的确定结果。
- 打开文档数（LRU）、补全缓存（每文档 LRU）、recent 窗口、查询队列均有
  界，占用不随运行时间无限增长。

## 4. 取消与超时

- 每个查询持有一个可轮询的 `QueryTask` 取消标志，在检查点
  （开始、缓存检查、计算前后）响应取消。
- 取消（显式或超时触发）后：不发布结果、不写缓存，响应一定是终态
  `CANCELLED` 或 `TIMEOUT`，且 `items` 必为空、不返回半成品。
- 超时由独立调度器在 `query-timeout-ms` 后触发；关闭文档会取消其上所有在
  途查询。
- 测试通过 `DelayHook`/`SleepingDelayHook` 以分片睡眠确定性地制造慢查询，
  不依赖大输入或时间运气。

## 5. 跨请求缓存

- 键为 `(version, position)`；只有文档仍处于该精确版本时缓存项才可用。
- 每次提交都使旧版本条目失效（`invalidateOlderThan`），已被编辑作废的旧
  结果不会再被读到。
- 慢查询晚到的结果通过 `putIfAbsent(..., currentVersion)` 做“版本门控 +
  键去重”：文档版本已前进时不写入，旧结果不能覆盖较新结果。
- 缓存命中返回的不可变列表与重算结果完全相同；命中与否不改变对外结果。

## 6. 持久化与重启

- 仅持久化**已提交快照**（文本、版本、按批次的 recent 名称）；派生模型与
  补全缓存不持久化，重启后惰性重建。
- 写入采用 `临时文件(CREATE_NEW) + flush/fsync + ATOMIC_MOVE`；不支持原子
  move 的文件系统退化为替换。崩溃只会留下旧快照或新快照之一，不会留下
  半个文件，未完成处理不留部分数据。
- 重启后恢复的文本/版本等于最后一次提交；固定输入、固定配置下重放同一批
  编辑，补全结果逐项可复现（`PersistenceRecoveryTest`）。
- `data-dir` 为空时禁用持久化，重启从空状态开始（默认）。

## 7. HTTP/回环

- 所有 HTTP 接口只监听 `127.0.0.1`：
  - `POST /api/documents/open`
  - `POST /api/documents/change`（返回 `ChangeOutcome`）
  - `POST /api/documents/close`
  - `POST /api/documents/completion`（异步，返回终态 `CompletionResponse`）
- 也可以不经网络直接使用 `ServiceFactory.create(properties)` 得到进程内
  服务（`demo/LocalLoopbackDemo` 演示），“客户端”完全由内存数据模拟。

## 8. 明确不承诺的范围

- 不是完整 Java 编译器：表达式类型推断是保守的局部启发式，无法推断类型时
  类型匹配加分为 0，但绝不影响作用域正确性与结果确定性。
- REBASE 精确支持紧邻的单个/多个中间提交（基于记录的绝对 span）；当陈旧
  编辑与无法平移的全文更新冲突时按策略拒绝，默认策略本就是 `REJECT`。
- 持久化保证单进程、本地文件系统上的原子性；不面向多进程并发写同一目录。
